# Phase 2. Load the data

**Agent:** `data-loader`
**Time:** 10 minutes
**AI on show:** GitHub Copilot writing the ingestion notebook

---

## The data

Four CSVs in `data/`, all synthetic, all generated by a seeded script.

| Table | Grain | Rows |
| --- | --- | --- |
| `fact_sales` | one sales order line | 64,335 |
| `dim_date` | one calendar day, 2024-01-01 to 2025-12-31 | 731 |
| `dim_product` | one product | 12 |
| `dim_store` | one store | 8 |

Those counts are exact. If yours differ, something dropped rows and you need to know
that now, not in phase 6 when Copilot returns a number nobody can explain.

---

## Path A. Portal upload, fastest

1. Open `LH_ContosoCoffee`.
2. Ribbon, `Get data`, `Upload files`. Select the four CSVs from `data/`.
3. Expand `Files` in the Explorer.
4. For each file: `...`, `Load to Tables`, `New table`. Accept the defaults.

Table names arrive lowercase. That is fine.

**Then check the types.** Open each table and confirm the money columns are numeric and
`date_key` is a date. If the loader inferred everything as string, use path B instead.
Almost every "Copilot gave a weird answer" problem in this demo starts here.

---

## Path B. Notebook, better demo

1. Upload the four CSVs to `Files/raw/` in the lakehouse.
2. Import `fabric/load_to_lakehouse.ipynb` into the workspace.
3. Attach it to `LH_ContosoCoffee`.
4. Run it.

The notebook applies an **explicit schema** rather than inferring, then verifies row
counts and total revenue.

### The version worth demoing

Delete the code cells. Keep the first markdown cell, which describes what the loader
must do. Then ask GitHub Copilot Chat to write it:

```text
Write a PySpark notebook cell that reads these four CSVs from Files/raw in the attached
lakehouse and writes each one as a managed delta table with the same name:
dim_date.csv, dim_product.csv, dim_store.csv, fact_sales.csv.

Requirements:
- Apply an explicit schema, do not infer. date_key as date, all *_amount columns as
  decimal(18,2), all *_key columns as integer, quantity as integer.
- Overwrite if the table exists.
- After writing, print the row count for each table.
```

Then compare what Copilot wrote to `fabric/load_to_lakehouse.ipynb`. Usually it is very
close. Where it differs is the interesting conversation, and the most common difference
is that Copilot infers the schema unless you insist.

---

## Verify. Always.

```python
EXPECTED = {"dim_date": 731, "dim_product": 12, "dim_store": 8, "fact_sales": 64335}
for table, expected in EXPECTED.items():
    print(table, spark.table(table).count(), expected)

spark.sql("SELECT SUM(net_amount) FROM fact_sales").show()
```

Total net revenue must be `412918.50`.

Compare against `python validation/ground_truth.py` on your machine. Same numbers, two
different engines, computed from the same seeded source. That is what verification looks
like.

---

## Two rules

1. **Tables, not files.** A Fabric data agent in phase 7 can only select lakehouse
   tables. If your data is sitting in `Files`, the agent cannot see it.
2. **Types matter more than they look.** Money as string means Copilot cannot aggregate
   it. A date as string means no time intelligence in phase 3.
